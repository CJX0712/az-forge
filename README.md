**AlphaZero 风格自我对弈 + MCTS，从零学会下 Connect-4。零依赖单文件 HTML，浏览器内训练。**

不喂任何人类棋谱、不查任何开局库、不做任何规则硬编码的策略——只有一个随机初始化的神经网络和一棵搜索树。
它靠**自己和自己下棋**变强。

```bash
git clone https://github.com/CJX0712/az-forge.git
# 直接用浏览器打开 index.html
```

想先看证据而不是动手：

```bash
node _smoke.js     # 无头自检（规则 / 编码 / 梯度检验 / MCTS 不变量 / 战术）
node _uicheck.js   # DOM stub 端到端（含 UI 自检）
node _probe.js 60  # 训练 60 局，打印 ASCII 棋局 + MCTS 逐列分析（人工读数用）
```

## 它真的会下棋吗

200 局自我对弈（约 7 分钟，单线程 Float64）后的成绩：

| 对手 | 训练前 | 训练后 |
|---|---|---|
| 随机走子 | 79.2% | **100.0%**（24 胜 0 负） |
| 一步贪心基线（能赢就赢、该堵就堵、否则随机） | 8.3% | **62.5%**（15 胜 9 负） |

`_probe.js` 打印的 MCTS 逐列分析更能说明问题。空盘开局时：

```
列         0      1      2      3      4      5      6
N          4      9     85     69     20      9      4     ← 搜索集中在中间两列
Q     -0.372 -0.126  0.205  0.198  0.141 -0.149 -0.310     ← 中间为正、边路为负
```

**中心列最强**是 Connect-4 的经典结论，没有人告诉过它，是它自己搜出来的。

给一个"黄方底行三连、红方唯一解是堵 col3"的局面：

```
N          7     17      6    441     14      9      6     ← 441 次访问压倒性集中
Q     -0.809 -0.463 -0.734 -0.048 -0.346 -0.516 -0.802     ← 只有 col3 不是惨败
```

再给一个"黄方双威胁、红方怎么堵都输"的死局，它给出全部 7 列的 Q ≈ −0.9 —— 正确判断自己已经输了。

## 架构

```
输入  2 × 6 × 7 平面（我方子 / 对方子，始终以当前玩家视角编码）
  │
  ├─ conv 3×3 pad1, 2 → K           ─┐
  ├─ K 通道残差块 × 2                 │ 共享躯干（K=16）
  │    y = relu(conv(relu(conv(x))) + x)
  │
  ├─ policy head: conv 1×1 K→4 → FC → 7 列 logits（非法列 mask 为 −1e9）
  └─ value head:  conv 1×1 K→2 → FC → 16 → FC → 1 → tanh
```

12,246 个参数，全部前向与反向手写，纯 `Float64Array`，无框架、无构建、无外部请求。

**搜索**：PUCT-MCTS
`a = argmax_a [ Q(a) + c_puct · P(a) · √ΣN / (1 + N(a)) ]`，根节点加 Dirichlet(0.3) 噪声（权重 0.25）保证探索，前 8 手按访问次数温度采样、之后取 argmax。

**训练信号**：一局结束后，把每个局面的**访问计数分布**当作策略目标 `π`，把最终结果当作价值目标 `z`：

```
L = CE(π_MCTS ‖ π_网络) + MSE(v, z)
```

这就是全部——没有人类数据，网络只是在拟合"搜索认为该怎么走"和"最后谁赢了"。

**数据增强**：Connect-4 左右对称，每个样本额外生成一份水平镜像（planes 与 π 同步翻转），零成本翻倍样本。启用它把 vs 贪心从 54.2% 提到了 62.5%。

## 一个值得记下的坑：ReLU 网络的梯度检验，ε 调小也没用

第一版自检里，ReLU 网络的梯度检验稳定报 `maxRel = 1.0`，而且从 ε=1e-4 一路调到 1e-7 **纹丝不动**。按常规经验（误差随 ε 下降 = 数值伪影，不变 = 真 bug），这铁定是反向传播写错了。

但**只有卷积的 bias 错，所有权重矩阵全是 1e-5 ~ 1e-10**。权重对、bias 错，不合常理。

真相是：bias 会**均匀抬升整个通道所有位置的预激活值**，于是一次扰动就能同时翻转该通道大批 ReLU 单元。有限差分这时量到的是跨折点的割线，解析梯度只统计活着的单元——两者从数学上就不该相等。ε 再小也救不了，因为翻转单元带来的贡献正比于 ε，与 ε 无关，是常数偏移。

**判别方法**：把激活换成光滑的 tanh（同一个 `forward`/`backward`，只换一个 `act` 参数）再验——`2.3e-7` 全绿。反向传播是对的。

**解决办法**：给检验加"折点感知"——扰动后重新前向，比较 ReLU 激活掩码；掩码变了就说明这个点 FD 不可测，跳过。调完 ReLU 网络本身也能被严格验证（`2.1e-6`），只是跳过约 55 个跨折点的参数。

这条比"把 ε 调小"更有用：**偏置类参数是折点最敏感的方向**，如果你在别的项目里看到"只有 bias 错、权重全对"，先怀疑折点，别急着改反向传播。

## 浏览器界面

- 点棋盘落子，你执红先手，AI 实时应手
- **MCTS 访问计数柱状图**：看 AI 在每一列上花了多少思考
- 训练 loss 曲线、自我对弈局数、样本缓冲、梯度步
- 「开始训练」让它在你眼前自我博弈；「评估基线」对比随机 / 一步贪心
- 「运行自检」在浏览器内跑完整不变量检查（约 1 秒）

## 已知限制

- 单线程朴素卷积，搜索规模有限（40–320 次模拟/步）。换成 Float32 + im2col 能快一个量级，但会牺牲梯度检验精度，这里选择保留 Float64 以便自检可信。
- 200 局的训练量远未收敛；继续训练 vs 贪心仍能往上走，但 Connect-4 的先手优势让"超过 60%"变得很快不再容易。
- 价值头的绝对数值（如 −0.45）只在同一代网络内可比较，不是 Elo。
- 未实现：批次推理（MCTS 的叶节点是逐样本推理的）、N-step 回报、优先级回放。
